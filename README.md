# DS鲸鱼娘 桌宠 · DS Whale Pet

把 [@氵六青](https://space.bilibili.com/11272072) 的 **DS鲸鱼娘** Live2D 模型，做成了一个**跟着你键鼠操作做反应**的 Windows 桌面宠物。

你敲键盘她跟着点头、打字飞快她会被带嗨、连点鼠标她会盯着你、滚页面她跟着滚、
安静太久她会犯困甚至睡着、你离开一阵再回来她会打招呼。

互动思路参考了 [BongoCat](https://github.com/ayangweb/BongoCat)（那只要跟着你敲键盘的猫）；
另外还接了自己的大模型聊天、一套互动音效，以及完整的模型原版按键表。

技术栈：Electron 31 + PIXI 6 + pixi-live2d-display 0.4（Cubism 4）+ uiohook-napi（全局键鼠钩子）。

| 方式 | 说明 |

## 二、输入联动（核心）

她跟着你**真实的键鼠操作**变表情，条件一变就换，不需要你按任何键。

| 优先级 | 她的反应 | 触发条件 | 表情 |
| --- | --- | --- | --- |
| 100 | 💤 睡着了 | 超过 **10 分钟**没碰键鼠 | 闭眼口水 |
| 80 | 😪 犯困 | 安静超过 **2.5 分钟**，或深夜 + 安静 30 秒 | 晕晕 |
| 75 | ❗ 你回来啦 | 离开 90 秒以上后重新动键鼠 | 感叹号 |
| 70 | 🤩 被你带嗨了 | 打字速度 **≥ 5 键/秒** | 星星眼 |
| 60 | ⌨️ 在陪你打字 | 打字速度 **≥ 0.8 键/秒** | —（只点头，不换表情） |
| 50 | 👆 被戳了 | 2.5 秒内点击 **≥ 3 次** | 调皮 |
| 45 | 🌀 跟着滚 | 刚滚过滚轮 | 问号 |
| 0 | 🐋 陪着你 | 兜底 | — |

### 2.1 打字时她在点菜板上写字（用的全是模型自带部件）

她身前那块白板是模型自带的**点菜板**，板子上画了三个图标：**↩ / ✏ / 🧽**，
平时都是**黑色**的。模型给了几个参数能把它们**变蓝**，所以不用画任何新图形，
「打字的时候亮、平时暗下来、按回车亮」就直接成立了：

| 你做什么 | 板子上 | 她本人 |
| --- | --- | --- |
| 敲键盘 | ✏ **变蓝** | 右手真的**举起笔**，`pointZ` 让手一下一下往下按 |
| 停手 1.2 秒 | ✏ 变回黑色 | 放下笔 |
| 按 **回车** | ↩ **变蓝**（700ms） | — |
| 按 **退格 / Delete** | 🧽 **变蓝**（700ms） | — |

板子上那个 ↩ 就是「回车」——它是模型原画里的撤回图标，我们只是让它亮起来。
`bi` / `chehui` / `pi` / `pointZ` 四个参数直接改，全部熄灭后再补写一帧 0 就收手，
免得跟用户手动开关这些表情的热键打架。

另外两条纯跟手的：

- **点头** —— `ParamAngleY` + `ParamBodyAngleZ` 叠一个指数衰减的脉冲，
  时间常数 120ms，连打时叠加，上限约 11°。
- **视线下偏** —— 打字时她的视线往下一点，像是也在看键盘。

> 点头幅度调过两轮：最初 2.4°/1.5°，用户反馈「根本看不出来」，现在 5.5°/4.5°。

### 2.2 克制的是「表情和台词」，不是「反馈」

- 「在陪你打字」**不换表情、不说台词** —— 你写代码时她不会一直跳；
  但她会**一直点头**，你能确定她还活着。
- 台词每次之间至少隔 **4 秒**，状态来回抖也不会刷屏。
- 反应切换有**迟滞**：升级（比如从发呆变成被你带嗨）立刻生效，
  降级要等满 1.2 秒 —— 否则计数卡在阈值上时表情会疯狂闪烁（实测踩过，见第八节）。

> 一条走错的路，记在这里免得重蹈：曾经想靠「每按一下键响一声哒」来保证反馈，
> 结果打字时一直有声音，反而很吵。**输入反馈应该是看得见的，不是听得见的。**

### 2.3 开关

右键菜单 / 托盘菜单 →「👀 跟随我的键鼠（输入联动）」。
关掉她就安静待着，只剩鼠标悬停时的视线跟随。

### ⚠️ 全局热键的注意事项

热键用系统级钩子（`uiohook-napi`）监听，**只监听、不拦截** —— 和 VTube Studio 一样。
所以 `Alt+1`~`Alt+4` 在浏览器里**也会**切换标签页，`Alt+F/E/V/H` 会打开浏览器菜单栏。
嫌吵就在托盘菜单里取消「⌨️ 全局热键」，所有功能依然能从右键菜单点。

> 顺带一提：全局钩子同时也负责**输入联动**，所以关掉热键不会影响她跟手。

## 四、和她聊天（接你自己的大模型）

右键菜单 →「💬 和她聊天」，或 `Ctrl+Alt+L`。

第一次打开是配置表单，填三样东西：

| 字段 | 例子 |
| --- | --- |
| 接口地址 | `https://api.deepseek.com/v1`（**要带 `/v1`**） |
| 模型名 | `deepseek-chat` |
| API Key | `sk-...`（Ollama / LM Studio 留空） |

DeepSeek / OpenAI / Moonshot / 智谱 / Ollama / LM Studio / one-api 都能用。
填完点「测试连接」，成功会把她的一句话回显出来。

### 4.1 她知道你在干嘛

每次请求都会把**你当前的键鼠活动**写进系统提示词。实测抓到的真实片段：

```
【你现在感知到的】
- 用户此刻在做什么：正在飞快地敲键盘
- 最近 2 秒按键速度：6.4 键/秒；最近点鼠标 0 次
- 距上次操作：1 秒
- 现在时间 15:02（下午）
- 你此刻的状态：🤩 被你带嗨了 —— 因为你打字快得飞起（≥ 5 键/秒）
```

所以同一句「在吗？」，你写代码写得飞起时和她安静发呆时，她回得不一样。

### 4.2 她的话会驱动表情和动作

回复第一行是标签行：

```
[表情:星星眼][动作:自拍简单]
嘿嘿，你终于来找我啦，我一直在这儿呢～
```

主进程解析出 `表情` / `动作`，喂给渲染进程的分层表情栈（`event` 层，9 秒后淡出）。
标签行不会显示给用户，流式输出时也会被实时剥掉。
表情和动作名走白名单校验，模型编造的名字会被静默忽略。

### 4.3 隐私

- API Key 只写在本机 `%APPDATA%\DSWhalePet\chat.json`，**不会上传**
- 渲染进程（网页那一层）**永远拿不到明文 key**，只拿得到 `sk-1····cdef` 掩码
- `chat.json` / `chat-history.json` 都已加进 `.gitignore`

## 五、互动音效

每类**状态变化**配一个音效，基调是「捏橡皮小黄鸭」。

> 注意这里的分寸：**声音只用来标记状态变化，不用来表示「你正在打字」。**
> 试过每按一下键响一声「哒」，打字时一直在响，很吵 —— 输入反馈应该是看得见的。

| 音效 | 触发 | 素材 |
| --- | --- | --- |
| 🦆 squeak | 摸摸头 / 点她 | Mixkit **Rubber duck squeak** |
| 😴 sleepy | 犯困 | Mixkit Cartoon vocal yawn |
| ⏰ wake | 你离开又回来 | Mixkit Cartoon toy whistle |
| 😋 nom / 🎾 boing / 🛁 splash | 旧互动保留 | Mixkit Chewing / Boing hit / Water splash |
| ✨ sparkle / 🎉 levelup | 旧互动保留 | Mixkit Magic wand sparkle / Achievement bell |
| 🚫 no | 操作被拒 | Mixkit Cartoon failure piano |

Mixkit 那 10 个素材来自 [Mixkit](https://mixkit.co/free-sound-effects/)（[Mixkit Free License](https://mixkit.co/license/#sfxFree)），
`tools/fetch-sfx.ps1` 可复现地重新下载并处理（去头静音 → 裁剪 → 压缩器 →
`loudnorm` → 尾淡出 → 单声道 22.05kHz/96kbps mp3），10 个共 **147 KB**。

处理时踩过一个坑：一开始按**峰值**归一化，结果 10 个素材的平均响度差了 18 dB
（`boing` −14 vs `nom` −32），`nom` 小到听不见；改成按响度归一后 `loudnorm` 单遍模式
对这么短的音频又不准，于是加了第二遍实测修正，最终 8 个精确落在 −20.5 dB。

开关和音量在菜单里：「🔊 互动音效」+「🔉 音效音量」（小/中/大，带试听）。

### 排障开关

改这个桌宠最难受的一点是**看不见也摸不着**：它是透明分层窗口（系统截屏抓不到），
它跟的是全局键鼠（没有真人按键就没有输入），而这台开发机还会直接拒绝合成输入。
下面四个开关就是为了把这三件事拆开。

**1. 分清「钩子没收到输入」还是「收到了但没表现」**

```powershell
# 每 5 秒打印追踪器看到的东西 + 每个原始事件
$env:DSHPET_INPUTDEBUG = "1"; npm start

# 每 4 秒轮播一个反应，完全不依赖真实输入
$env:DSHPET_DEMO = "1"; npm start
```

`DSHPET_DEMO=1` 会把 8 个反应依次演一遍，日志里同时给出
`演示 -> 💤 睡着了｜表情 [闭眼口水]｜音效 无｜台词 Zzz……`。

`DSHPET_INPUTDEBUG=1` 的心跳长这样：

```
[raw] 追踪器 键/秒=0 点击=0 滚轮=0 空闲=25s 反应=idle
```

`空闲` 一直在涨、`键/秒` 一直是 0 → 钩子根本没收到事件（安全软件拦截 / 权限问题）；
数字在动但反应不对 → 问题在规则或渲染层。

**2. 不从键盘、直接验证「主进程 → 渲染层」这一段**

```powershell
$env:DSHPET_FAKEKEYS = "A,B,Enter,C,Backspace"; npm start
```

它走 `sendKeyPulse` 这条真实链路，所以能验证点菜板图标的接线。
实测输出：

```
假按键已开启：A B Enter C Backspace（每 2.5 秒一个）
[pet] 点菜板图标：笔亮 回车灭 橡皮灭     <- A
[pet] 点菜板图标：笔灭 回车灭 橡皮灭     <- 停手 1.2 秒
[pet] 点菜板图标：笔灭 回车亮 橡皮灭     <- Enter
[pet] 点菜板图标：笔灭 回车灭 橡皮亮     <- Backspace
```

**3. 直接从 WebGL framebuffer 抓图**

```powershell
$env:DSHPET_SHOT = "freeze,bi:bi=1,chehui:chehui=1"
$env:DSHPET_SHOT_DIR = "$env:TEMP\petshots"
npm start
```

`DSHPET_SHOT` 是逗号分隔的脚本，每项出一张图；`名字:参数=值+参数=值` 可以临时压住
任意参数。它是**成对**拍的（先 `名字-off` 再 `名字-on`），因为 Idle 动作一直在动，
拿两张相隔很久的图去 diff 会把人物整体位移都算成差异。

桌宠是透明、无边框、始终置顶的分层窗口，GDI 的 `CopyFromScreen` 抓不到它
（`CAPTUREBLT` 也只是时灵时不灵）—— 之前排查「看不到宠物」时在这上面浪费过很多时间。
从 `gl.readPixels` 直接读像素拿到的就是真正画出来的东西，配合 `tools/param-range.js`
（列出某个参数在动作和表情里的取值范围）就能把模型自带的部件全摸清楚。

## 七、实现上的几个要点

**1. 原模型的 `model3.json` 是残缺的**

原模型包里只声明了 `Moc / Textures / Physics / DisplayInfo`，**完全没有 `Motions` 和
`Expressions` 段**（那些信息只存在于 `c_0120.vtube.json` 里，只有 VTube Studio 认）。
Cubism 运行时只读 `model3.json`，所以 `app/tools/make-model3.js` 会把 44 个表情和
8 个动作补声明进去，同时把 7 个动作的 `Loop` 改成 `false`（见下一条）。

**2. 分层表情栈（「表情随情况自动变」的落地点）**

三个来源往同一个池子里放表情，用层级决定优先级：

| 层 | 来源 | 行为 |
| --- | --- | --- |
| `react` | 输入联动引擎按你的键鼠活动推导 | 条件一变自动整体替换 |
| `prop` | 热键手动开关 | 一直保留到再按一次 |
| `event` | 点击 / 聊天回复的即时反应 | 带 TTL 自动淡出 |

同名表情只保留层级最高的那个。混合模式按原始 exp3 里的 `Blend` 走（基本都是 `Add`），
所以多个表情能叠加。写入发生在 `beforeModelUpdate` 钩子里 —— 那个位置正好在
`coreModel.update()` 之前，写进去的值就是这一帧真正拿去绘制的值。

**3. 输入联动引擎是纯逻辑**

`app/input.js` 不依赖 Electron 和 DOM，`node tools/test-input.js` 用假时钟跑 48 条断言，
覆盖打字速度档位、点击/滚轮窗口、空闲与睡觉、离开又回来、每条规则可达性、迟滞行为。
测试跑出来的都是真问题：凌晨时段规则会盖过猛敲键盘、阈值抖动导致表情闪烁。

**4. 视线跟随：别用库自带的 `model.focus()`**

它的实现是「把光标换算到模型局部坐标 → 归一化 → `atan2` 求方向 → 喂一个**单位向量**
给 focusController」。单位向量模长恒为 1，而 `updateFocus()` 里是
`addParameterValueById(ParamAngleX, 30 * controller.x)` —— 所以**永远是满偏转**，
眼睛只会贴在左边或右边，看着像没在跟随。

这里改成直接驱动 `focusController`，按「光标相对模型中心的偏移量」做**比例**控制。
实测（`petX` 约 1850）：光标在正中时 `ParamAngleX ≈ 0`，偏右才 `+8`、偏左才 `−24`。

**5. 全屏透明窗口的「按像素穿透」和它的两个大坑**

窗口铺满工作区，默认 `setIgnoreMouseEvents(true, { forward: true })`，桌面其它地方的
点击完全不受影响。渲染进程用 `gl.readPixels` 读回**鼠标位置那一个像素的 alpha**，
只有落在模型不透明的地方才把窗口切成可交互。

- **坑一：切成可交互之后 `mousemove` 就不再转发了。** 指针坐标会冻在进入那一刻，
  渲染进程永远发现不了你已经离开面板。修法：主进程用 `screen.getCursorScreenPoint()`
  **全程 50ms 轮询**补坐标（实测一次会话里转发总共只送到过 1 个 mousemove）。
- **坑二：`focusable: false` 会让输入框「有光标但打不了字」。** Windows 把键盘事件送给
  前台窗口，而它不是。修法：光标一进面板就把窗口切成可激活，之后由 Windows 自己完成激活。

**6. 动作系统踩的四个坑**

- 8 个动作文件的 `Meta.Loop` 全是 `true`（原本给 VTube 用，靠外部控制时长）。
  而 `MotionManager` 里 IDLE 在有动作在播时直接拒绝、NORMAL 也盖不过 NORMAL，
  只有「播完」才把 `currentPriority` 归零 —— 循环动作永远不 complete，
  她会**卡在第一个播出去的动作上**。修法：`make-model3.js` 把 7 个改成 `Loop:false`。
- `model.motion()` 返回的 Promise 是**「已开始」不是「已播完」**（实测 4~6ms 就 resolve）。
  按「播完」处理的话，每个动作刚起步就被自己掐掉。现在只信 `Meta.Duration`。
- 动作留下的**道具参数没人收**。Idle 驱动的 89 个参数和所有动作完全不重叠
  （Idle 用 `Param73`/`maoshou*`，动作动的是 `chuipaopao*`/`phone*`/`pengshui`），
  所以吹泡泡播完回待机后 `chuipaopao*` 会停在最后一帧 —— **泡泡永远挂在脸上**。
- 库的 `currentPriority` / `currentGroup` / `complete()` 都挂在 **`mm.state`** 上，
  不在 `mm` 本身。写成 `mm.complete()` 会被 `typeof` 守卫静默跳过：不报错，但没用。

> 测量陷阱：库的每帧顺序是
> `motion.update → saveParameters → … → beforeModelUpdate → coreModel.update() → loadParameters()`。
> 帧末的 `loadParameters()` 会把「存档值」恢复回来，所以**在帧外读参数看到的仍是旧值**。
> 要看真实效果必须在 `beforeModelUpdate` 里读。

**7. 「总在最前」会漂，而且有个反直觉的坑**

实测同一个版本，有时起来是 `alwaysOnTop: true`、有时是 `false`（竞态）。
所以主进程有条看门狗每 3 秒确认一次，掉了就补回来并写日志。

坑在于：**别用 `win.moveTop()` 去「顺便提到最前」** —— 它内部是
`SetWindowPos(HWND_TOP)`，而 `HWND_TOP` 会**清掉 `WS_EX_TOPMOST`**，
等于 `setAlwaysOnTop(true)` 刚设好就被自己撤销了。

## 八、常见问题

**看不到宠物？**
1. 先看托盘有没有鲸鱼图标 —— 有就说明程序活着。
2. **双击启动器「没反应」是正常的**：程序已经在跑，单实例锁会让新进程立刻退出。
   这时去**托盘**右键 → 点「📌 总在最前」或「🎯 回到右下角」，她就会回来。
3. 可能被别的置顶窗口挡住了：托盘菜单关掉再打开「📌 总在最前」。
4. 位置跑到屏幕外了：菜单点「🎯 回到右下角」。
5. 还是不行看日志：`%APPDATA%\DSWhalePet\pet.log`。

**她不理我的键鼠？**
1. 菜单里确认「👀 跟随我的键鼠」是勾上的。
2. 看日志有没有 `全局钩子已启动：热键 …｜输入联动 开`；没有就是安全软件拦了全局钩子。
3. 反应是**按 500ms 一次评估**的，而且降级有 1.2 秒迟滞 —— 不是每个键都有反馈，
   这是刻意的（见第二节「刻意克制」）。
4. 想确认她到底识别到了什么：菜单 →「👀 她在干什么」，能看到打字速度、点击次数、空闲秒数。

**面板点不动 / 输入框打不了字？**
先把鼠标**移进面板停半秒再点**（窗口从穿透切成可交互需要一点时间）。
再看日志有没有这几行：`光标进入面板：窗口已允许被激活` / `setIgnoreMouseEvents(false)` /
`输入框获得焦点: #c-base`。

**存档在哪？** `%APPDATA%\DSWhalePet\settings.json`（位置/大小/开关）和 `chat.json`（聊天配置）。

## 九、调试脚本（`tools/`）

- `shot.ps1 grab x y w h out.png` —— 用带 `CAPTUREBLT` 的 `BitBlt` 截屏
  （普通 `CopyFromScreen` 截不到透明窗口，别拿它判断「有没有渲染出来」）
- `shot.ps1 diff a.png b.png [容差]` —— A/B 逐像素对比，报出差异像素数与包围盒
- `keytest.ps1 "0x12:1:0;0x51:1:0;…"` —— 注入真实按键组合。
  **两个陷阱**：`bScan` 必须给真实扫描码（传 0 时字母键能蒙对，PageUp 不行）；
  C# 源码要保持纯 ASCII（中文注释会被按 ANSI 读，吃掉下一行）
- `mousekey.ps1 move|click x y | type "文字" | pos` —— 注入鼠标/键盘。
  坐标是**物理像素**（125% 缩放要 ×1.25）；移动必须走 `SendInput`，
  `SetCursorPos` 不产生 Electron `forward` 依赖的底层鼠标事件
- `mock-llm.js [port]` —— 假的 OpenAI 兼容服务，不需要真 key 就能端到端测聊天链路
