# DS鲸鱼娘 桌宠

拿 [@氵六青](https://space.bilibili.com/11272072) 的 **DS鲸鱼娘** Live2D 模型做的 Windows 桌宠。

她会跟着你的键鼠动：你敲键盘，她在旁边点头、举起笔在板子上写写画画；你打字打得飞起，
她会被你带嗨；连点几下鼠标她会盯着你看；你滚页面她跟着滚。要是十分钟不理她，她就睡着了，
再回来她还会跟你打招呼。

这个点子的出处是 [BongoCat](https://github.com/ayangweb/BongoCat)，那只跟着你敲键盘的猫。
我本来打算直接用，但手上只有鲸鱼娘的模型，就自己用 Electron 重写了一个 ——
所以代码跟 BongoCat 没有任何关系（它是 Tauri + Vue），只是抄了"跟着键鼠做反应"这个想法。

顺手还加了个聊天框，能接你自己的大模型 API。

技术栈：Electron 31 + PIXI 6 + pixi-live2d-display（Cubism 4），
全局键鼠钩子用 [uiohook-napi](https://github.com/SnosMe/uiohook-napi)。

## 先说怎么跑

| 双击哪个 | 什么时候用 |
| --- | --- |
| `启动桌宠.vbs` | 平时用这个，安静启动，不闪黑框 |
| `启动桌宠.bat` | 出毛病了用这个，留一个控制台窗口给你看报错 |

跑起来她会出现在主显示器右下角，托盘多一个鲸鱼图标。

**没有窗口可以关，退出只能走托盘菜单或者右键菜单里的「退出」。**
第一次用找不到人退，别急，右键点她身上就行。

依赖和模型都已经在仓库里了。换台机器只需要在 `app/` 目录里跑一次 `npm install`。

## 她的反应规则

规则列表从上往下看，第一条成立的，就是她此刻的状态：

| 优先级 | 状态 | 触发条件 | 表情 |
| --- | --- | --- | --- |
| 100 | 💤 睡着了 | 超过 10 分钟没碰键鼠 | 闭眼口水 |
| 80 | 😪 犯困 | 安静超过 2.5 分钟，或者深夜 + 安静 30 秒 | 晕晕 |
| 75 | ❗ 你回来啦 | 离开 90 秒以上，又重新动键鼠 | 感叹号 |
| 70 | 🤩 被你带嗨了 | 打字速度 ≥ 4 键/秒 | 星星眼 |
| 60 | ⌨️ 在陪你打字 | 打字速度 ≥ 0.8 键/秒 | 不换表情 |
| 50 | 👆 被戳了 | 2.5 秒内点了 3 次以上鼠标 | 调皮 |
| 45 | 🌀 跟着滚 | 刚滚过滚轮 | 问号 |
| 0 | 🐋 陪着你 | 兜底 | 不换表情 |

有几点是我特意压着的，因为第一版做得太吵：

- 「在陪你打字」不换表情、不说台词。你写代码的时候她不该一直在旁边跳。
- 台词之间至少隔 4 秒，不然状态在阈值上抖一抖就刷屏了。
- 状态切换有迟滞：**升级立刻生效**（比如从发呆变成被带嗨），
  **降级要等满 1.2 秒**。一开始我让驻留对所有切换生效，结果"你已经开始打字了，
  她 1.2 秒后才理你"——只对降级迟滞才两个问题都解决。

## 打字的时候她在干嘛

这块折腾最久，因为中间走了一大段弯路，值得单独说。

她身前那块白板是**模型自带的**，叫「点菜板」。板子上画了三个图标：

```
↩      ✏      🧽
```

这三个图标平时是黑色的。模型作者留了参数能把它们**变蓝**，所以
"打字的时候亮、停下来暗下去、按回车就亮回车"这件事，我一个像素都不用画：

| 你做什么 | 板子上 | 她本人 |
| --- | --- | --- |
| 敲键盘 | ✏ 变蓝 | 右手真的举起笔，手一下一下往下按 |
| 停手 1.2 秒 | ✏ 变回黑 | 把笔放下 |
| 按回车 | ↩ 变蓝（700ms） | 不动 |
| 按退格 / Delete | 🧽 变蓝（700ms） | 不动 |

板子上那个 ↩ 就是"回车"，它原本是模型原画里的撤回图标，我只是让它亮起来而已。
对应 `bi` / `chehui` / `pi` / `pointZ` 四个参数。熄灭之后我会再补写一帧 0 就收手，
免得跟用户手动开关这些表情的热键打架。

除了这个，还有两条纯跟手的：一是**点头**（`ParamAngleY` + `ParamBodyAngleZ` 叠一个
衰减脉冲），二是**打字时视线往下偏一点**，像也在看你的键盘。

### 弯路：我一开始做成了每按键响一声"哒"

想法是"每一下输入都得有回应"，听起来很合理。结果打字的时候一直在响，非常吵，
被骂了。后来才想明白：

> 输入反馈应该是**看得见**的，不是听得见的。

顺便，声音模块后来整个被删了，现在这桌宠一点声音都没有。

### 另一条弯路：点头幅度

第一版幅度只有 2.4°/1.5°，反馈是"根本看不出来"。调大之后又变成"跟鬼畜一样"——
因为当时每按一键就往角度上砸一个脉冲，每次按键都是一个阶跃，高频打字就成了抽搐。

现在改成按键只抬"能量"，角度由一个连续相位推出来，中间还过了一层 90ms 低通。
最大单帧变化从 5.5° 降到 0.4° 左右，看着就是在跟着你的手速微微点头。

## 脚下的状态条

她脚边挂着一条常驻读数：

```
🤩 被你带嗨了    ⌨️ 8.0 键/秒
```

打字速度超过 4 键/秒数字会变红。点鼠标的时候会多一段"👆 3 次"，
闲下来超过 5 秒才显示"12s 没动"（正在打字的时候显示这个没意义）。

这条东西一开始是放在二级菜单里的，被吐槽"你藏在二级界面里是给鬼看嘛"——
确实，想知道自己敲多快，谁会先展开两层菜单。现在既挂在脚下，也摆在一级菜单顶上。
不想要可以在「其他设置 → 状态条」关掉。

## 菜单为什么分三层

因为设置项和动作项混在一起的时候，两样都难找。

一级是右键菜单，打开就能看到实时状态和常用动作；二级放"选择类"的东西（表情、动作、大小）；
所有"设置类"的开关都收进了三级窗口「⚙️ 其他设置…」。

一级菜单大概长这样：

```
🤩 被你带嗨了
⌨️ 4.3 键/秒　👆 2 次　🕐 隔 1 秒
─────────────────────
💬 和她聊天
─────────────────────
😊 表情 ▸        🎬 动作 ▸
✨ 随机换表情     ↩️ 按键归位
📏 大小 ▸
─────────────────────
⚙️ 其他设置…      ❌ 退出
```

「其他设置」是个 HTML 面板，不是原生菜单。倒不是因为它好看，
而是**原生菜单放不下滑条，也没法在选项底下写一行说明**。
面板复用聊天面板那套定位：都塞在 `#panels` 里，自动贴着宠物排，左边放不下就翻到右边。

## 聊天

右键菜单「💬 和她聊天」，或者 `Ctrl+Alt+L`。

第一次打开是个配置表单，填三样：

| 字段 | 例子 |
| --- | --- |
| 接口地址 | `https://api.deepseek.com/v1`（**要带 `/v1`**） |
| 模型名 | `deepseek-chat` |
| API Key | `sk-...`（Ollama / LM Studio 可以留空） |

DeepSeek、OpenAI、Moonshot、智谱、Ollama、LM Studio、one-api 都能用。
填完点「测试连接」，她会回你一句，说明通了。

### 她知道你在干嘛

每次请求都会把你的键鼠活动写进系统提示词。这是真实抓到的一段：

```
【你现在感知到的】
- 用户此刻在做什么：正在飞快地敲键盘
- 最近 2 秒按键速度：6.4 键/秒；最近点鼠标 0 次
- 距上次操作：1 秒
- 现在时间 15:02（下午）
- 你此刻的状态：🤩 被你带嗨了 —— 因为你打字快得飞起（≥ 4 键/秒）
```

所以同一句"在吗"，你写代码写得飞起时和她安静发呆时，回得不一样。

### 她的话会驱动表情

回复第一行是标签行，长这样：

```
[表情:星星眼][动作:自拍简单]
嘿嘿，你终于来找我啦，我一直在这儿呢～
```

主进程把 `表情` / `动作` 解析出来，喂给表情栈（`event` 层，9 秒后淡出）。
标签行不会显示给你，流式输出的时候就会被实时剥掉。表情和动作名走白名单校验，
模型要是编了个不存在的名字，会被静默忽略。

### 隐私

API Key 只写在本机 `%APPDATA%\DSWhalePet\chat.json`，不会上传。
渲染进程那一层永远拿不到明文 key，只拿得到 `sk-1····cdef` 这样的掩码。
`chat.json` 和 `chat-history.json` 都在 `.gitignore` 里。

## 出问题了看这里

代码里留了几个环境变量，专门用来分辨"是哪一层坏了"。
会需要它们是因为这东西**看不见也摸不着**：它是透明分层窗口，系统截屏抓不到；
它跟的是全局键鼠，没有真人按键就没有输入。不把这几层拆开，只能瞎猜。

**分清"钩子没收到输入"还是"收到了但没表现"**

```powershell
# 每 5 秒打印追踪器看到的东西 + 每个原始事件
$env:DSHPET_INPUTDEBUG = "1"; npm start

# 每 4 秒轮播一个反应，完全不依赖真实输入
$env:DSHPET_DEMO = "1"; npm start
```

`DSHPET_DEMO` 会把 8 个反应挨个演一遍。
`DSHPET_INPUTDEBUG` 的心跳长这样：

```
[raw] 追踪器 键/秒=0 点击=0 滚轮=0 空闲=25s 反应=idle
```

`空闲` 一直在涨、`键/秒` 一直是 0，说明钩子根本没收到事件（安全软件拦截 / 权限问题）。
数字在动但反应不对，那问题在规则或者渲染层。

**不碰键盘，直接验证"主进程 → 渲染层"这一段**

```powershell
$env:DSHPET_FAKEKEYS = "A,B,Enter,C,Backspace"; npm start
```

它走的是 `sendKeyPulse` 这条真实链路，所以能验点菜板图标的接线。
后面加 `@110` 可以指定速度（毫秒）：

```
假按键已开启：A B Enter C Backspace（每 110 ms 一个）
[pet] 点菜板图标：笔亮 回车灭 橡皮灭     <- A
[pet] 点菜板图标：笔灭 回车灭 橡皮灭     <- 停手 1.2 秒
[pet] 点菜板图标：笔灭 回车亮 橡皮灭     <- Enter
[pet] 点菜板图标：笔灭 回车灭 橡皮亮     <- Backspace
```

**抓图**

```powershell
# 从 WebGL framebuffer 直接读像素，拍模型
$env:DSHPET_SHOT = "freeze,bi:bi=1,chehui:chehui=1"
$env:DSHPET_SHOT_DIR = "$env:TEMP\petshots"

# 整页拍（DOM + canvas），拍 HTML 面板
$env:DSHPET_PAGESHOT = "settings"     # 或者 chat
```

`DSHPET_SHOT` 是个逗号分隔的脚本，每项出一张图，
`名字:参数=值+参数=值` 可以临时把任意参数压成你要的值。
它是**成对**拍的（先 `名字-off` 再 `名字-on`）——因为 Idle 动作一直在动，
拿两张隔得远的图去 diff，人物的整体位移会把差异淹掉。

顺带一提，GDI 的 `CopyFromScreen` 截不到这种透明置顶的分层窗口，
`CAPTUREBLT` 也只是时灵时不灵。我在这上面浪费过很多时间，
最后发现从 `gl.readPixels` 直接读才靠谱 —— 拿到的就是真正画出来的东西。

## 几个把我坑惨的地方

写在这里一半是备忘，一半是万一你也要拿别的模型做同样的东西，能少走点路。

**原模型的 `model3.json` 是残缺的。**
包里只声明了 `Moc / Textures / Physics / DisplayInfo`，`Motions` 和 `Expressions` 段
完全没有——那些信息只存在于 `c_0120.vtube.json` 里，只有 VTube Studio 认。
Cubism 运行时只读 `model3.json`，所以 `make-model3.js` 会把 44 个表情和 8 个动作补声明进去，
顺手把 7 个动作的 `Loop` 改成 `false`（下面会说为什么）。

**分层表情栈。**
三个来源往同一个池子里放表情，按层级决定谁赢：
`react`（输入联动推导的，条件一变整体替换）、`prop`（热键开关的，一直留着）、
`event`（点击和聊天的即时反应，带 TTL 自动淡出）。
同名的只留层级最高的那个。写入发生在 `beforeModelUpdate` 钩子里，
那个位置刚好在 `coreModel.update()` 之前，写进去的值就是这一帧真正拿去绘制的值。

**引擎是纯逻辑，所以能单测。**
`app/input.js` 不依赖 Electron 和 DOM，`node tools/test-input.js` 用假时钟跑 47 条断言。
测试跑出来的都是真问题：凌晨时段规则会盖过猛敲键盘、阈值抖动导致表情闪烁。

**视线跟随：别用库自带的 `model.focus()`。**
它内部是"把光标换算到模型局部坐标 → 归一化 → `atan2` 求方向 → 喂一个**单位向量**"。
单位向量模长恒为 1，而 `updateFocus()` 里是 `addParameterValueById(ParamAngleX, 30 * controller.x)`，
所以**永远满偏转**，眼睛只会贴在左边或右边，看着像根本没跟随。
改成直接驱动 `focusController`，按光标相对模型中心的偏移量做比例控制就好了。

**全屏透明窗口的"按像素穿透"有两个坑。**
窗口铺满工作区，默认 `setIgnoreMouseEvents(true, { forward: true })`，
桌面别的地方点击完全不受影响。渲染进程用 `gl.readPixels` 读鼠标那个像素的 alpha，
只有落在模型不透明的地方才把窗口切成可交互。然后：

- 切成可交互之后，`mousemove` 就不再转发了，指针坐标会冻在进入那一刻，
  渲染进程永远发现不了你已经离开面板。修法是主进程用 `screen.getCursorScreenPoint()`
  全程 50ms 轮询补坐标（实测一次会话里，转发总共只送到过 1 个 mousemove）。
- `focusable: false` 会让输入框"有光标但打不了字"，因为 Windows 把键盘事件送给前台窗口，
  而它不是。修法是光标一进面板就把窗口切成可激活，之后交给 Windows 自己完成激活。

**动作系统踩了一串。**
8 个动作文件的 `Meta.Loop` 全是 `true`（原本给 VTube 用，靠外部控制时长）。
但 `MotionManager` 里 IDLE 在有动作在播时直接拒绝、NORMAL 也盖不过 NORMAL，
只有"播完"才把 `currentPriority` 归零——循环动作永远不 complete，
她会**卡在第一个播出去的动作上**。这就是上面把 7 个改成 `Loop:false` 的原因。

另外 `model.motion()` 返回的 Promise 是"已开始"而不是"已播完"（实测 4~6ms 就 resolve 了），
按"播完"处理的话每个动作刚起步就被自己掐掉。现在只信 `Meta.Duration`。

还有，动作留下的道具参数没人收。Idle 驱动的 89 个参数和所有动作完全不重叠
（Idle 用 `Param73`/`maoshou*`，动作动的是 `chuipaopao*`/`phone*`/`pengshui`），
所以吹泡泡播完回待机之后 `chuipaopao*` 会停在最后一帧——**泡泡永远挂在脸上**。
这个 bug 是用户报的。

最后，库的 `currentPriority` / `currentGroup` / `complete()` 都挂在 `mm.state` 上，
不在 `mm` 本身。写成 `mm.complete()` 会被 `typeof` 守卫静默跳过：不报错，但也没用。

> 这里有个测量陷阱值得单独记一笔。库的每帧顺序是
> `motion.update → saveParameters → … → beforeModelUpdate → coreModel.update() → loadParameters()`。
> 帧末那个 `loadParameters()` 会把"存档值"恢复回来，
> 所以**在帧外读参数看到的仍然是旧值**。要看真实效果必须在 `beforeModelUpdate` 里读。

**"总在最前"会漂。**
实测同一个版本，有时起来是 `true`、有时是 `false`，是个竞态。
所以主进程有条看门狗每 3 秒确认一次，掉了就补回来并写日志。

坑在于**别用 `win.moveTop()` 去"顺便提到最前"**：它内部是 `SetWindowPos(HWND_TOP)`，
而 `HWND_TOP` 会**清掉 `WS_EX_TOPMOST`**，等于 `setAlwaysOnTop(true)` 刚设好就被自己撤销了。
这个 bug 的表现是"宠物有时候打不开"。

## 常见问题

**看不到宠物？**

先看托盘有没有鲸鱼图标，有就说明程序活着，只是你看不见她。
然后**双击启动器"没反应"是正常的**——程序已经在跑了，单实例锁会让新进程立刻退出。
去托盘右键，点「📌 总在最前」或者「🎯 回到右下角」，她就回来了。
（这两个现在在「其他设置」面板里。）都不行就看日志：`%APPDATA%\DSWhalePet\pet.log`。

**她不理我的键鼠？**

去「其他设置」确认「跟随我的键鼠」是勾上的。然后看日志有没有
`全局钩子已启动：热键 46 个｜输入联动 开`，没有就是被安全软件拦了。
另外，反应是 500ms 评估一次、降级还有 1.2 秒迟滞，所以不是每个键都有反馈，这是故意的。
想知道她到底识别到了什么，看她脚下那条状态条就行。

**面板点不动 / 输入框打不了字？**

把鼠标移进面板停半秒再点——窗口从穿透切成可交互需要一点时间。
还不行就翻日志，找这几行：`光标进入面板：窗口已允许被激活` /
`setIgnoreMouseEvents(false)` / `输入框获得焦点`。

**存档在哪？**

`%APPDATA%\DSWhalePet\` 下面。`settings.json` 存位置和开关，`chat.json` 存聊天配置。

## `tools/` 里那堆脚本

- `shot.ps1 grab x y w h out.png` —— 带 `CAPTUREBLT` 的 `BitBlt` 截屏。
  普通 `CopyFromScreen` 截不到透明窗口，别拿它判断"有没有渲染出来"
- `shot.ps1 diff a.png b.png [容差]` —— 逐像素对比，报差异像素数和包围盒
- `keytest.ps1 "0x12:1:0;0x51:1:0;…"` —— 注入真实按键组合。
  两个陷阱：`bScan` 必须给真实扫描码（传 0 的时候字母键能蒙对，PageUp 就不行了）；
  C# 源码要保持纯 ASCII（中文注释会被按 ANSI 读，吃掉下一行）
- `mousekey.ps1 move|click x y | type "文字" | pos` —— 注入鼠标键盘。
  坐标是物理像素（125% 缩放要 ×1.25）；移动必须走 `SendInput`，
  `SetCursorPos` 不产生 Electron `forward` 依赖的那种底层鼠标事件
- `inputcheck.ps1` —— 注入端自检：当前进程到底能不能合成键鼠输入。
  我这台开发机就是直接拒绝 `SetCursorPos` 的，这时候"桌宠没反应"跟桌宠一点关系都没有
- `mock-llm.js [port]` —— 假的 OpenAI 兼容服务，不用真 key 就能端到端测聊天链路
