# DS鲸鱼娘 桌宠 · DS Whale Pet

把 [@氵六青](https://space.bilibili.com/11272072) 的 **DS鲸鱼娘** Live2D 模型，做成了一个能**养**的 Windows 桌面宠物。

不只是"会动的模型"：她有饱食度、心情、精力、清洁、好感度和等级；表情**由条件实时推导**而不是随机播；
你喂她、陪她玩、给她洗澡、哄她睡觉，她会记住，也会在你不管她的时候闹脾气。
**还能接你自己的大模型 API 跟她聊天** —— 她说话的口气取决于此刻的养成状态，而她说的话又会驱动她的表情和动作。

技术栈：Electron 31 + PIXI 6 + pixi-live2d-display 0.4（Cubism 4 运行时）+ 自研养成引擎。

## 一、快速开始

| 方式 | 说明 |
| --- | --- |
| 双击 `启动桌宠.vbs` | **推荐**，静默启动，没有黑框 |
| 双击 `启动桌宠.bat` | 会闪一个控制台窗口，出问题时用这个看报错 |

启动后她出现在**主显示器右下角**，托盘多一个鲸鱼图标。
**退出程序只能从托盘菜单或右键菜单点「❌ 退出」。**

> 仓库里已经带了 `node_modules` 之外的依赖声明和模型，clone 下来在 `app/` 目录跑一次 `npm install` 即可。

## 二、养成系统

### 2.1 五项数值

| 数值 | 图标 | 自然变化 | 说明 |
| --- | --- | --- | --- |
| 饱食度 | 🍚 | **−4.2 / 小时** | 低了会饿，低于 28 开始抱怨，低于 12 直接虚脱 |
| 心情 | 💗 | 向"基线"回归 | 基线由其它三项 + 好感度决定；心情差了她会生气、难过 |
| 精力 | ⚡ | **−3.0 / 小时**（睡觉时 **+14 / 小时**） | 低于 14 就撑不住了，归零会**自己睡着** |
| 清洁 | 🫧 | **−2.1 / 小时** | 脏了她会不舒服 |
| 好感度 | ❤️ | 0–100 | 互动涨，长期冷落会缓慢下降 |

**离线也照算**：关掉程序期间数值继续衰减，但你离开超过 **8 小时**就不再补算 —— 上班一天回来不会发现她已经饿死。

### 2.2 情绪规则表（条件驱动表情的核心）

每隔 20 秒重新评估一次，**从高优先级往下找第一条成立的条件**，找到什么情绪，表情/台词/待机动作就立刻跟着变。
所以她的表情不是随机的，是"因为饿了""因为困了""因为你半天没理她"。

| 优先级 | 情绪 | 触发条件 | 对应表情 |
| --- | --- | --- | --- |
| 100 | 💤 睡觉中 | 正在睡觉 | 闭眼口水 |
| 95 | 😵 饿扁了 | 饱食度 < 12 | 哭 + 流汗 |
| 88 | 😪 累瘫了 | 精力 < 14 | 晕晕 + 闭眼口水 |
| 80 | 😠 生气了 | 心情 < 18 | 生气 |
| 70 | 🍚 肚子饿了 | 饱食度 < 28 | 流汗 |
| 62 | 🫧 有点脏 | 清洁 < 26 | 流汗 |
| 56 | 🥺 被冷落了 | > 45 分钟没互动 且 心情 < 75 | 悲伤 |
| 50 | 😢 有点难过 | 心情 < 36 | 悲伤 |
| 42 | 🌙 深夜犯困 | 本地时间 23:00–06:00 | 晕晕 |
| 34 | 🤩 超开心 | 心情 > 85 且 2 分钟内玩过 | 星星眼 |
| 24 | 😊 心情不错 | 心情 > 74 | —（靠自主行为加道具） |
| 12 | 🙂 平静 | 心情 > 55 | — |
| 0 | 🐋 发呆 | 兜底 | — |

状态面板里会**直接写出当前情绪和原因**，比如 `😵 饿扁了 · 饱食度低于 12`，一眼能看出表情为什么变了。

### 2.3 六个互动

| 互动 | 快捷键 | 冷却 | 效果 | 前置条件 |
| --- | --- | --- | --- | --- |
| 🍚 喂食 | `Ctrl+Alt+F` | 45s | 饱食 +22、心情 +6、清洁 −3 | 饱食 ≤ 94 |
| 🎾 玩耍 | `Ctrl+Alt+P` | 60s | 心情 +15、精力 −11、饱食 −4、清洁 −4 | 精力 ≥ 15、醒着 |
| 🤚 摸摸头 | `Ctrl+Alt+M` 或**直接左键点她** | 3s | 心情 +4、好感 +1 | — |
| 🛁 洗澡 | `Ctrl+Alt+C` | 120s | 清洁 +42、心情 +3、精力 −4 | 清洁 ≤ 92 |
| 🎁 送礼物 | `Ctrl+Alt+G` | 300s | 心情 +20、好感 +4、清洁 +2 | — |
| 💤 睡觉 / 叫醒 | `Ctrl+Alt+S` | 4s | 切换睡眠状态 | — |

每个互动都有冷却和前置条件 —— 吃饱了喂不进去、没力气玩不动。这是刻意的：
**要你看状态做决策，而不是无脑连点。**

### 2.4 等级 · 称号 · 成就

- 互动给经验，累计经验升级，共 **10 级**
- 每级有称号：`陌生的鲸 → 点头之交 → 有点眼熟 → 朋友 → 好朋友 → 贴心崽 → 黏人鲸 → 小棉袄 → 灵魂伴侣 → 命中注定`
- 升级会额外奖励心情和好感
- **9 个成就**：第一次投喂、投喂 20 次、一起玩 10 次、被摸头 50 次、洗了 10 次澡、收到 5 份礼物、到达 Lv.5、好感度 60、好感度 90

### 2.5 自主行为

没人管的时候她也会自己找事做 —— 每 25~80 秒按当前情绪挑一件事：说句话、做个动作、戴上墨镜/蝴蝶结贴纸、或者纯粹发呆。
情绪不同，能挑的事也不同（饿的时候只会念叨吃的，超开心的时候会自己自拍）。

## 四、和她聊天（接你自己的大模型）

右键菜单 →「💬 和她聊天」，或 `Ctrl+Alt+L`。

第一次打开是配置表单，填三样东西就能用：

| 字段 | 说明 | 例子 |
| --- | --- | --- |
| 接口地址 | OpenAI 兼容的 baseUrl，**要带 `/v1`** | `https://api.deepseek.com/v1` |
| 模型名 | 模型 id | `deepseek-chat` |
| API Key | 没有就留空（本地模型通常不需要） | `sk-...` |

常见的几家：

| 服务 | 接口地址 | 模型名示例 |
| --- | --- | --- |
| DeepSeek | `https://api.deepseek.com/v1` | `deepseek-chat` |
| OpenAI | `https://api.openai.com/v1` | `gpt-4o-mini` |
| Moonshot | `https://api.moonshot.cn/v1` | `moonshot-v1-8k` |
| 智谱 | `https://open.bigmodel.cn/api/paas/v4` | `glm-4-flash` |
| Ollama（本地） | `http://127.0.0.1:11434/v1` | `qwen2.5:7b` |
| LM Studio（本地） | `http://127.0.0.1:1234/v1` | 你加载的模型名 |
| one-api / new-api | 你的网关地址 + `/v1` | 自定 |

填完点「测试连接」，成功会把她的一句话回显出来。请求走 Electron 的 `net.fetch`，
所以**会自动使用系统代理设置**（这点很重要：直连 GitHub / OpenAI 都不通的网络里，她照样能说话）。

### 4.1 她会「带着状态」跟你说话

每次请求都会把**她当前的养成状态**写进系统提示词。这是实测抓到的真实提示词片段：

```
【你现在的状态】
- 等级 Lv.3「有点眼熟」，已经和用户相处 36 分钟
- 饱食度 12/100，心情 35/100，精力 89/100，清洁 81/100
- 对用户的好感度 12/100
- 现在时间 18:33（晚上）
- 此刻的情绪：😵 饿扁了 —— 因为饱食度低于 12
```

所以同一句「在吗？」，她回得完全不一样：

| 她的状态 | 她回你 |
| --- | --- |
| 吃饱喝足、心情不错 | `[表情:星星眼][动作:自拍简单]` 嘿嘿，你终于来找我啦，我一直在这儿呢～ |
| 饿到 12、心情 35 | `[表情:流汗]` 肚子好饿……你有吃的吗？ |

提示词里还写死了语气规则：饿 → 念叨吃的；困/深夜 → 打哈欠；心情低 → 闹别扭；
好感高 → 更黏人；好感低 → 客气疏远。所以养成状态不是摆设，真的会改变她的性格表现。

### 4.2 她的话会驱动表情和动作

回复的第一行是标签行：

```
[表情:星星眼][动作:自拍简单]
嘿嘿，你终于来找我啦，我一直在这儿呢～
```

主进程解析出 `表情` / `动作`，直接喂给渲染进程的**分层表情栈**（`event` 层，9 秒后自动淡出），
于是她边说边做表情。标签行不会显示给用户 —— 流式输出时也会被实时剥掉。

表情和动作都做了**白名单校验**：模型编一个不存在的表情名会被静默忽略，不会报错。
模型要是耍脾气返回 JSON 或不给标签，也能兜住（见 `parseReply`）。

### 4.3 聊天也算陪伴

每聊一句都会：刷新「最近互动」时间（所以聊天能治「被冷落」）、心情 +2、好感度 +0.5、经验 +2。
奖励有 **15 秒冷却**防刷，但聊天本身不冷却。

对话历史存在本机（`chat-history.json`，最多 200 条），重启后她还记得你们聊过什么。

### 4.4 隐私

- API Key 只写在本机 `%APPDATA%\DSWhalePet\chat.json`，**不会上传到任何地方**（只有你自己填的接口地址会收到它）
- 渲染进程（网页那一层）**永远拿不到明文 key**，只拿得到 `sk-1····cdef` 这样的掩码
- `chat.json` / `chat-history.json` 都已加进 `.gitignore`

她做每个动作都有对应的音效，基调是「捏橡皮小黄鸭」。

| 音效 | 触发时机 |
| --- | --- |
| 🦆 小黄鸭 squeak | 摸摸头 / 点她 |
| 😋 咀嚼 nom | 喂食 |
| 🎾 弹跳 boing | 玩耍 |
| 🛁 水花 splash | 洗澡 |
| ✨ 闪光 sparkle | 送礼物 / 解锁成就 |
| 🎉 升级 levelup | 等级提升 |
| 😪 哈欠 sleepy | 哄她睡觉 / 精力耗尽自己睡着 |
| ⏰ 起床 wake | 把她叫醒 |
| 😊 开心 happy | 从负面情绪被哄好（饿了→吃饱之类） |
| 🚫 不行 no | 操作被拒（「已经吃得很饱啦」） |

开关和音量在右键菜单 / 托盘菜单里：**🔊 互动音效** 勾选框 + **🔉 音效音量**（小/中/大，带「试听」）。
音量默认 60%。连点摸头被静默吞掉时不会发声，所以不会刷屏。

### 音效来源与处理

10 个音效都来自 [Mixkit](https://mixkit.co/free-sound-effects/) 的免费音效库（[Mixkit Free License](https://mixkit.co/license/#sfxFree)）：

| 音效 | Mixkit 素材 | 原长 → 裁剪 |
| --- | --- | --- |
| squeak | **Rubber duck squeak** | 0.67s → 0.62s |
| happy | Funny Giggling | 2.09s → 1.40s |
| nom | Chewing something crunchy | 0.94s → 0.89s |
| boing | Boing hit sound | 1.24s → 0.95s |
| splash | Water splash | 1.48s → 1.15s |
| sparkle | Magic wand sparkle | 2.50s → 1.60s |
| levelup | Achievement bell | 2.40s → 1.80s |
| sleepy | Cartoon vocal yawn | 1.75s → 1.45s |
| no | Cartoon failure piano | 2.31s → 1.00s |
| wake | Cartoon toy whistle | 1.21s → 0.95s |

重新下载并处理（需要 ffmpeg）：

```powershell
pwsh tools/fetch-sfx.ps1
```

处理链是：**去头静音 → 裁剪到适合桌宠的长度 → 压缩器压一下动态 → `loudnorm` 响度归一 → 尾淡出 → 单声道 22.05kHz / 96kbps mp3**。

这里有个坑值得记：一开始我按**峰值**归一化，结果 10 个素材的**平均响度差了 18 dB**
（`boing` −14 dB vs `nom` −32 dB），`nom` 会小到听不见。改成按**响度**归一，
并且因为 `loudnorm` 单遍模式对这么短的音频不准（`nom` 差了 14 dB），又加了第二遍
实测修正。最终 8 个精确落在 −20.5 dB，剩下两个是受 −1 dB 峰值上限保护的"尖端"素材。
10 个合计 **147 KB**。

### 想要纯合成版本？

`app/tools/make-sfx.js` 还能用振荡器 + 噪声 + 包络**现场合成**一套（输出 wav）：

```bash
cd app && npm run build:sfx
```

删掉 `app/sfx/*.mp3`，渲染层会在 mp3 加载失败时**自动退回 wav**，不需要改任何配置。
（合成版的好处是版权完全归属本项目、不依赖任何外部素材；代价是真实录音的质感更好。）

## 八、实现上的几个要点

**1. 原模型的 `model3.json` 是残缺的**

原模型包里只声明了 `Moc / Textures / Physics / DisplayInfo`，**完全没有 `Motions` 和 `Expressions` 段**
（那些信息只存在于 `c_0120.vtube.json` 里，只有 VTube Studio 认）。Cubism 运行时只读 `model3.json`，
所以 `app/tools/make-model3.js` 会把 44 个表情和 8 个动作补声明进去：

```bash
cd app && node tools/make-model3.js
```

**2. 分层表情栈（条件驱动表情的落地点）**

`pixi-live2d-display` 自带的 `ExpressionManager` 一次只能生效一个表情，但原按键表明显允许叠加
（头顶鲸 + 墨镜 + 表情同时存在）。而且原始 `.exp3.json` 的 `Blend` 基本都是 `Add`，天生可叠加。

所以渲染进程在 `beforeModelUpdate` 钩子里自己按 `Add / Multiply / Overwrite` 逐帧写参数，并把表情分成三层：

| 层 | 来源 | 行为 |
| --- | --- | --- |
| `mood` | 养成引擎按条件推导 | 条件一变自动整体替换 |
| `prop` | 热键手动开关 | 一直保留到再按一次 |
| `event` | 交互 / 点击的即时反应 | 带 TTL，自动淡出 |

同名表情只保留层级最高的那个，高层不会被低层打断。**"表情随条件变化"就是 `mood` 层每次被整体替换的结果。**

**3. 养成引擎和聊天模块都是纯逻辑，能单测**

`app/game.js` 和 `app/chat.js` 都不依赖 Electron 和 DOM。
`node tools/test-game.js` 用假时钟跑 79 条断言（衰减、离线封顶、每条情绪规则可达性、冷却、升级、成就、音效事件、存档往返），
`node tools/test-chat.js` 用假 fetch 跑 80 条断言（配置归一、提示词拼装、回复解析、**跨块 SSE 流式解析**、各类错误分支）。

测试跑出来的都是真 bug：等级数组差一位、满级时经验区间除零、构造时用墙钟导致自主行为永不触发、
聊天模块里嵌套模板字符串的语法错。

**4. 聊天怎么同时接进养成和表情系统**

```
用户输入
  → buildSystemPrompt(她的快照)      把饱食度/心情/好感度/时间/当前情绪写进提示词
  → requestChat (SSE 流式)           走 Electron net.fetch，自动吃系统代理
  → parseReply                       拆出 [表情:xxx][动作:xxx] 和正文
  → game.noteChat()                  涨好感 / 心情 / 经验（15 秒冷却）
  → dispatchEvents([expression, motion])  喂进分层表情栈的 event 层
```

两个方向都是通的：**状态影响她说什么**（提示词），**她说什么影响她长什么样**（表情栈）。
表情/动作名走白名单校验，模型编造的名字会被静默忽略。

**5. 全屏透明窗口的「按像素穿透」和它的两个大坑**

窗口铺满工作区，默认 `setIgnoreMouseEvents(true, { forward: true })`，桌面其它地方的点击完全不受影响。
渲染进程用 `gl.readPixels` 读回**鼠标位置那一个像素的 alpha**，只有落在模型不透明的地方才把窗口切成可交互。
状态面板是 DOM 不是画布，所以额外用 `getBoundingClientRect` 判了一次矩形。

这套东西踩了两个坑，都写在这里免得后人再踩：

**坑一：切成可交互之后，`mousemove` 就不再转发了。**

Electron 文档只说 `forward` 在 `ignore: true` 时生效 —— 反过来说，一旦调用
`setIgnoreMouseEvents(false)`，转发就停了。后果是渲染进程的指针坐标**冻在进入面板那一刻**，
它永远发现不了你已经离开面板，窗口就卡死在「可交互」状态，后续点击全落到错误的地方。

修法：可交互期间由主进程用 `screen.getCursorScreenPoint()` 每 60ms 轮询补坐标
（`startCursorPoll()`），不可交互时再交还给转发。

**坑二：`focusable: false` 会让输入框「有光标但打不了字」。**

这个窗口平时是 `focusable: false`（不抢前台焦点、不进 Alt+Tab）。但 Windows 会把键盘事件送给
**前台窗口**，而它根本不是前台窗口 —— 于是你能点进输入框、能看到光标在闪，打字却全跑到别的程序去了。

修法：光标一进面板就把窗口切成可激活（`setFocusable(true)`），之后你点输入框时由 Windows
自己完成激活 —— 比在 JS 里 `win.focus()` 硬猜可靠得多。另外 `need-focus` 那段必须写
「已经是焦点窗口就立刻返回」，否则 `win.focus()` 会让输入框失焦又重获、`focus` 事件再触发一次，
滚成每秒几十次的死循环（这个是真踩到了，日志里刷了 20 行）。

**坑三（测试用的，不是程序问题）：合成鼠标点击只让第一次生效。**

`SendInput` 明明返回 `2/2`，但第二次之后的点击会被系统路由到别处，换成 `focusable: true`
或关掉穿透都一样。所以验证交互只能靠真鼠标或者让用户确认，别拿注入点击当真理。

**6. 动作系统一共踩了四个坑（都是真机上报出来的）**

**① 模型里 8 个动作的 `Meta.Loop` 全是 `true`。**
这套动作原本给 VTube Studio 用，那边靠 `DeactivateAfterKeyUp` 在**外部**控制时长，所以 Loop 不可信。
而 `MotionManager` 里 IDLE 优先级在有动作在播时直接拒绝、NORMAL 也盖不过 NORMAL，
只有「播完」才会把 `currentPriority` 归零 —— 循环动作永远不 complete，
于是她卡在第一个播出去的动作上，之后连待机都起不来。
`tools/make-model3.js` 会把 7 个动作改写成 `Loop:false`（idle 保持 true）。

**② `model.motion()` 返回的 Promise 是「已开始」不是「已播完」。**
实测 4~6ms 就 resolve(true)。按「播完」处理的话，每个动作刚起步就被自己掐掉。
现在只信 `Meta.Duration` 定时器，Promise 只用来识别被拒（`ok === false`）。

**③ 动作留下的「道具参数」没人收。**
实测 Idle 驱动的 89 个参数和所有动作**完全不重叠**（Idle 用 `Param73`/`maoshou*` 那套，
动作动的是 `chuipaopao*` / `phone*` / `pengshui`）。所以吹泡泡「播完」回待机之后，
`chuipaopao*` 会停在最后一帧 —— **泡泡永远留在她脸上**。这就是「动作没有归位」的真相。

修法：记下每个动作驱动哪些参数，动作结束时把 Idle 不碰的那些加进 `clearedParams`，
在 `beforeModelUpdate` 里每帧写回模型初始值。归位（`PageUp`+`PageDown`）和双击会一次性收掉全部。

> 测量这里有个陷阱：库的每帧顺序是
> `motion.update → saveParameters → … → beforeModelUpdate → coreModel.update() → loadParameters()`。
> 帧末的 `loadParameters()` 会把「存档值」恢复回来，所以**在帧外读参数看到的仍是旧值**。
> 一开始我就是这么测的，误判成"没复位"。要看真实效果必须在 `beforeModelUpdate` 里读。

**④ 库的字段藏在 `mm.state` 上。**
`currentPriority` / `currentGroup` 和复位方法 `complete()` 都挂在 `mm.state`，
不在 `mm` 本身。写成 `mm.complete()` 会被 `typeof` 守卫静默跳过 ——
不报错，但优先级从没复位过。正确写法是 `mm.state.complete()`、`mm.stopAllMotions()`。

另外加了个动作看门狗：超过预计时长还没回待机，就强制收尾，免得又卡死。

**7. 视线跟随：别用库自带的 `model.focus()`**

库的实现是「把光标换算到模型局部坐标 → 归一化 → `atan2` 求方向 → 喂一个**单位向量**
给 focusController」。单位向量模长恒为 1，而 `updateFocus()` 里是
`addParameterValueById(ParamAngleX, 30 * controller.x)` —— 所以**永远是满偏转**：
眼睛只会贴在左边或右边，看着像没在跟随。

这里改成直接驱动 `focusController`，按「光标相对模型中心的偏移量」做**比例**控制。
实测（`petX` 约 1850）：

| 光标 x | ParamAngleX | ParamEyeBallX |
| --- | --- | --- |
| 240（远左） | −30.0 | −1.00 |
| 1337 | −24.5 | −1.00 |
| 1840（正中心） | **−0.3** | **−0.20** |
| 2000 | **+8.1** | **+0.30** |

纵向同理：光标在她上方 `AngleY=+30`，下方 `AngleY=−30`。

**8. 还有一个更隐蔽的：归位不能清「受保护参数」**

视线跟随的结果是写进 `ParamAngleX/Y/Z`、`ParamEyeBallX/Y`、`ParamBodyAngleX` 的，
眨眼写 `ParamEyeLOpen/ROpen`，呼吸写 `ParamBreath`。
而 `自拍` / `番茄酱` / `重锤出击` 这些动作**也驱动 `ParamAngleX/Y/Z`** ——
于是它们会被那份「动作留下的参数」名单收进去，归位后每帧强制写 0，
**正好把视线跟随和眨眼的输出覆盖掉**：眼睛不跟鼠标了、也不眨眼了。

所以 `clearMotionParams` 里有一道 `PROTECTED_PARAMS` 白名单。归位时保护的参数
从 58 个降到 46 个，视线和眨眼都不受影响。

## 九、常见问题

**看不到宠物？**
1. 先看托盘有没有鲸鱼图标 —— 有就说明程序活着。
2. 可能被别的置顶窗口挡住了：托盘菜单关掉再打开「📌 总在最前」。
3. 位置跑到屏幕外了：菜单点「🎯 回到右下角」。
4. 还是不行看日志：`%APPDATA%\DSWhalePet\pet.log`（每次启动都写自检信息，含缩放、位置、像素 alpha）。

**存档在哪？** `%APPDATA%\DSWhalePet\pet-state.json`（养成）和 `settings.json`（位置/大小/开关）。
删掉 `pet-state.json` 就是从零开始，删掉 `settings.json` 会重置窗口设置。

**热键没反应？** 多半是安全软件拦了全局键盘钩子，看日志里有没有 `uiohook-napi 不可用` 或 `globalShortcut 回退模式`。

**想改养成数值？** 直接编辑 `pet-state.json` 里的 `stats` / `affection` / `exp`，重启生效。

**面板点不动 / 输入框打不了字？**
1. 先把鼠标**移进面板停半秒再点**。窗口从「穿透」切成「可交互」需要一点时间，
   贴着边缘猛点可能会漏掉第一下。
2. 看日志里有没有这几行，能直接定位卡在哪一步：
   - `光标进入面板：窗口已允许被激活` —— 没这行说明指针没被识别成进了面板
   - `setIgnoreMouseEvents(false)  可交互=true` —— 没这行说明窗口还是穿透状态
   - `输入框获得焦点: #c-base` —— 没这行说明点击没落到输入框上
3. 如果日志显示都正常但就是打不了字，多半是别的程序抢着当前台窗口，重新点一次输入框即可。

**没有声音？**
1. 右键菜单确认 **🔊 互动音效** 是勾上的，再用 **🔉 音效音量 → ▶ 试听** 试一下。
2. 试听有声音、互动没声音 → 看日志里有没有 `表情开：…` 但缺 `音效播放成功`，
   多半是那个音效没被触发（比如操作被拒时只响 `no`）。
3. 完全没声音 → 检查 Windows 音量合成器里 Electron 是不是被单独静音了。
4. 日志里出现 `音效播放失败` 或 `音效已装载 0 个` → `app/sfx/` 里的 wav 丢了，
   跑 `cd app && npm run build:sfx` 重新生成。

**聊天没反应 / 报错？**
1. 点面板里的「测试连接」，它会直接用当前配置打一次接口，报错信息比较具体
   （`接口返回 401`＝key 不对；`解析不了域名`＝地址写错或要挂代理；`连接被拒绝`＝本地模型没启动）
2. 接口地址**要带 `/v1`**（智谱是 `/api/paas/v4`），别只填到域名
3. 本地模型（Ollama / LM Studio）记得先在设置里允许跨域，或确认监听在 `127.0.0.1`
4. 想直接看链路，可以在启动前设环境变量，它会自动发一句话并把结果写进日志：
   ```powershell
   $env:DSHPET_CHAT_PROBE = "你好呀"; .\启动桌宠.bat
   ```
   日志在 `%APPDATA%\DSWhalePet\pet.log`

## 十、调试脚本（`tools/`）

写这个桌宠时踩到一个坑：**GDI 的 `CopyFromScreen` 截不到透明（分层）窗口**，
很容易误判成"没渲染出来"。所以留了两个小工具：

- `tools/shot.ps1 grab x y w h out.png` —— 用带 `CAPTUREBLT` 的 `BitBlt` 截屏
- `tools/shot.ps1 diff a.png b.png [容差]` —— A/B 逐像素对比，报出差异像素数与包围盒
- `tools/keytest.ps1 "0x11:1:0;0x12:1:0;0x46:1:0;0x46:0:0;0x12:0:0;0x11:0:0"` —— 注入真实按键组合，测全局热键
- `tools/mousekey.ps1 move|click x y | type "文字" | pos` —— 注入鼠标移动/点击/打字，用来测面板交互。
  **注意两点**：坐标是**物理像素**（这台机器 125% 缩放，CSS 坐标要 ×1.25）；
  移动必须走 `SendInput`，`SetCursorPos` 不产生 Electron `forward` 依赖的底层鼠标事件。
  另外它只能让第一次点击生效（见第八节坑三），所以结论要交叉验证。
- `tools/mock-llm.js [port]` —— **假的 OpenAI 兼容服务**，不需要真 key 就能端到端测聊天链路。
  它会打印收到的 system prompt（方便确认状态真的写进去了），并按提示词里的饱食度返回不同表情：

  ```powershell
  node tools/mock-llm.js 8787          # 一个窗口起 mock
  # 另一个窗口：把接口地址填成 http://127.0.0.1:8787/v1，模型名随便填
  ```

  > 写这个 mock 的时候自己踩了个坑：`req.on('close')` 在请求体读完时就会触发，
  > 会把还没发出一个字节的流式定时器清掉，客户端就永远卡在等流结束。要用 `res.on('close')`。
  > 这个 bug 是靠着「连接一直是 Established + 日志里没有回复」才定位到的。
